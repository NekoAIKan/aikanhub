# 速率限制

速率限制用于保护服务稳定性，并帮助不同用户公平共享资源。限制可能来自账号、分组、令牌、模型或站点全局策略。

## 触发场景

常见触发原因包括：短时间内请求过于密集、并发任务过多、特定模型临时拥挤、账号分组策略较严格，或令牌被设置了更小的使用范围。

## 处理方式

当收到限流响应时，客户端应当降低并发、延迟重试，并为批量任务加入队列。不要在失败后立即无限重试，这会让任务更慢，也可能触发更严格的保护策略。

建议业务侧记录请求 ID、模型、时间和错误信息，方便管理员定位具体限制来源。

## 管理员建议

管理员可以按分组设置默认策略，为高优先级业务分配独立分组，并定期查看错误日志和消耗趋势。如果某类任务经常触发限流，应优先调整调用节奏，再评估是否需要更高等级策略。
