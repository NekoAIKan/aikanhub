# 计费与积分

AIKanHub 用统一的"积分 (credits)"作为计费单位，与具体的后端模型解耦。

## 积分单位

- **1 积分 = $0.01**
- 钱包以积分显示。所有充值、扣费、退款、邀请奖励都用积分。
- 你不会在控制台看到原始 token 数或后端美元成本 —— 我们做了一层稳定的抽象，让用量预算更容易做。

## 视频生成单价

按"每秒"计费，价格随分辨率上升：

| 分辨率 | 单价 |
| --- | --- |
| 480p | ~0.7 积分/秒 |
| 720p (1280×720) | ~1.5 积分/秒 |
| 1080p (1920×1080) | ~2.9 积分/秒 |

举例：

| 视频规格 | 积分消耗 | 美元约值 |
| --- | --- | --- |
| 720p × 5 秒 | ~7 积分 | ~$0.07 |
| 1080p × 5 秒 | ~15 积分 | ~$0.15 |
| 1080p × 10 秒 | ~30 积分 | ~$0.30 |

> 上表为常用规格的近似值。最终结算以服务端真实计算为准（多退少补）。

## 计费流程

视频生成是异步的，所以扣费分两步：

### 1. 提交时：预扣预估额度

提交任务的瞬间，平台用**最坏情况估算**（最高分辨率 + 最长时长）从钱包预扣一笔。这是为了：

- 防止你在排队期间接连提交把钱包打成负数。
- 在第一时间把"这次任务大约要花多少"反映到余额上。

如果钱包不足以覆盖预扣，返回 402，**不会进入排队**。

### 2. 完成时：按真实规格结算

任务完成（`succeeded`）时，平台用后端返回的**真实分辨率和时长**重新计算：

- 真实消耗 < 预扣 → 把差额退回钱包。
- 真实消耗 > 预扣 → 不会再扣（你享受估算保守的好处），但会记入日志。
- 任务失败（`failed`）→ 预扣全额退回。

整个结算过程是原子的，你在控制台看到的余额永远是结算后的最终值。

## 充值

控制台 → 充值，目前支持：

- Stripe（信用卡 / Apple Pay / Google Pay）
- 部分地区可使用 USDT / 微信 / 支付宝（具体支付通道以控制台显示为准）

充值即时到账。1 美元 = 100 积分（线性兑换，不打折也不溢价）。

## 邀请奖励

- 通过你邀请码注册的用户成功验证邮箱后，你会立即获得邀请奖励积分。
- 奖励积分进入"邀请额度 (Aff Quota)"账户，可在控制台一键转入主钱包。
- 邀请奖励不计入历史消费金额（管理员用历史消费做风控统计时不会因此误伤）。

详见 [Beta Program](./beta-program.md#邀请奖励规则)。

## 常见问题

**Q：我的 720p × 5s 任务实际扣了 7 积分但有时是 8 积分，为什么？**

A：分辨率字段除了 `720p` 之外可能取到 `1280x720` 等等，后端在结算时会对齐到最近的标准档位。少量浮动是计费舍入精度造成的，不会超过 ±1 积分。

**Q：失败任务真的全退？我提交了 100 个失败任务会不会扣钱？**

A：真的全退。我们有专门的对账机制保证 `failed` 状态的任务在结算阶段把预扣金全额退回。如果你在日志里看到失败但余额没退，请到控制台提交工单。

**Q：用 Beta 邀请额度跑生产可以吗？**

A：可以。邀请额度在结算上和钱包额度等价，唯一区别是来源标签。

**Q：积分会过期吗？**

A：常规账户的积分**不会过期**。但长期不活跃（>180 天无登录无 API 调用）的账户，剩余积分可能在合规清理时归还为 $0；具体策略见服务条款 / 控制台公告。

**Q：能不能开发票 / 开收据？**

A：Stripe 充值会自动发邮件收据。如需公司抬头发票（中国大陆增值税普票 / 专票），请在充值后联系客服并提供税号。

**Q：为什么不直接用 USD 计价？**

A：用积分是为了将来更灵活地引入新模型 / 新供应商而不影响你的预算逻辑 —— 同一个 720p 5 秒视频今后可能跑在不同后端上，但你看到的依然是稳定的 ~7 积分。
